CYCLE 2 — TEST CONNECTION (our backend → your API)
-------------------------------------------------------------------
POST https://testserver.misrapp.com/api/EtaDocument/Documents

Headers:
  EtaAuthentication: <auth key, 128 chars from credential.txt>
  EtaTimestamp:      <Unix seconds, string>
  EtaSignature:      Base64(HMAC-SHA256(payload, secret))
  EtaAPIVersion:     2
  Content-Type:      application/json

Body (exact string in HMAC):
  {"Documents":[]}

HMAC payload = authKey + timestamp + rawJsonBody
             (no spaces added between parts)

Secret: EtaCyrus@1234

We treat auth as OK if response has no ERR_AUTH_*, ERR_HMAC_*, ERR_IP_DENY.
VAL_* validation errors on empty array = still auth OK.

-------------------------------------------------------------------
CYCLE 3 — SUBMIT A REAL RECEIPT (certification / manual today)
-------------------------------------------------------------------
1. GET  /api/eta/preview/{invoice_id}
       → returns {"Documents":[...]}  (no call to your API)

2. POST /api/eta/submit-preview/{invoice_id}
       → our backend POSTs to YOUR API:

POST {BaseUrl}/EtaDocument/Documents
Same HMAC headers as test.
Body: {"Documents":[ { one Sales Receipt document } ]}

Document mapping:
  InternalId     = invoice number
  UniqueId       = {BranchCode}-R-{invoice_id}-{invoice_number}
  DocumentType   = 3 (sale), 4 (return — Phase 2)
  BranchCode     = B01 (from settings)
  PosSerial      = P01 (from settings)
  Customer*      = customer record OR walk-in defaults (cash = configurable name)
  DocumentDetails = invoice line items
  ItemCode       = product eta_item_code OR barcode
  VAT            = product vat_rate

-------------------------------------------------------------------
CYCLE 4 — QR ON PRINTED RECEIPT
-------------------------------------------------------------------
After submit succeeds (Phase 2 will automate this):

  GET {BaseUrl}/EtaDocument/QrCode?UniqueId={UniqueId}
  HMAC: authKey + timestamp + ""  (empty body for GET)

We store QrUrl in eta_submissions.qr_url.

Cashier receipt modal polls (every 4 sec):
  GET /api/eta/invoice/{invoice_id}/receipt
  → returns qr_url when status=accepted

Frontend NEVER calls your API directly — only our backend does.

-------------------------------------------------------------------
CYCLE 5 — AUTO SUBMIT AFTER SALE (Phase 2 — planned)
-------------------------------------------------------------------
Sale completes → DB commit → enqueue_sale (try/except, no raise)
→ eta_submissions status=pending
→ background worker POST /Documents + GET /QrCode
→ receipt QR appears when ready

Returns: same with DocumentType=4 + ReferenceUUID to original receipt.
